# Diagnostics

Every diagnostic of `gsql-lsp` carries a code (shown in brackets by
`gsql-lsp check` and in most editors). This page explains each one. The
settings named in the last column can turn checks off (see the
[configuration](../README.md#configuration)).

Checks that depend on the schema (types, attributes, VALUES lists) use the
vertex and edge types declared in the workspace; they stay quiet when the
workspace has no schema or when a type is changed by `ALTER` statements whose
effect on the database cannot be known.

## No schema

| Code | Severity | Meaning | Setting |
| --- | --- | --- | --- |
| `stub-declaration` | warning | A `BUILTIN ...` declaration in a file other than the generated reference of the built-ins (`reference-<version>.gsql` in the cache folder). | |
| `no-schema` | warning | The workspace has no schema (no `CREATE VERTEX`/`ADD VERTEX` in any file the server can see), so the checks of vertex types, edge types, attributes and VALUES lists are off. Shown once per file, on the name of the first query or loading job that uses a vertex or edge type, naming that type. A file outside every workspace folder (also one given to `gsql-lsp check`; a directory given to it uses the `.gsqlroot` above it the same way) is checked against all `.gsql` files under the nearest folder above it that has a `.gsqlroot` file, else against the `.gsql` files in its own folder; to give a project a root without git, put a `.gsqlroot` file in the project folder. | `noSchemaNotice` |

## Syntax

| Code | Severity | Meaning |
| --- | --- | --- |
| `syntax-error` | error | The parser could not read the text. Common mistakes get a specific explanation: a missing `;`, a missing `,` between ACCUM statements, `POST ACCUM` written as two words, `ELSEIF`, an IF without END, an extra END (but not after an `ELSE IF` chain: see Limitations in the README), a SELECT without FROM, a malformed edge step, a trailing comma (in parameter lists, ACCUM and PRINT lists, accumulator declarations and ORDER BY; the quick fix removes it), an IF without `THEN` or a WHILE or FOREACH without `DO` (the quick fix inserts it), `name type = value` instead of `DEFAULT value`, unterminated strings, and a shell command that continues on the next line (`SHOW`, `GRANT` and other commands end at the end of their line). A misspelled keyword is reported once, as `did you mean FROM instead of FORM?`, instead of as the errors it causes: the server parses the statement again with similar keywords in its place. The same goes for misspelled commands and for the keywords of GRANT, REVOKE, EXPORT and IMPORT scopes. When no keyword explains a statement whose errors the parser reports only as `unexpected X` or `missing X`, the server tries removing one token near the first error, or inserting one of `) ] } ; , = ( [ { END THEN DO` after the token before it, and reports the statement as that one mistake (`unexpected x in query body: the statement parses without it`, `missing ) after 1 in argument list`) with up to three quick fixes (`Remove x`, `Insert )`); these are guesses, so "fix all" never applies them. Messages that say more (trailing comma, `=>`, unclosed IF, a missing name or expression) are kept. See [error-recovery.md](error-recovery.md). Quick fixes: the correction, inserting a missing token, and the GSQL spelling of the mistakes above; the certain ones are also applied by "fix all" (`source.fixAll`). |

## Names and declarations

| Code | Severity | Meaning | Setting |
| --- | --- | --- | --- |
| `undeclared-accumulator` | error | A global (`@@x`) or vertex-attached (`@x`) accumulator is used but not declared in the query. Quick fixes: change it to a similar declared accumulator (`@scor` for `@score`), or declare it, with a type guessed from its use. | — |
| `duplicate-declaration` | error | The name is already declared in the same scope. | — |
| `undefined-name` | warning | An identifier in a query is not a parameter, variable, vertex set, alias or known type. Quick fix: similar names. | `undefinedNames` |
| `unknown-function` | warning | A function call names no built-in function, query or tuple, but one with a similar name exists (`cout` for `count`). Functions defined only in the database (C++ user-defined functions) are not reported. Quick fix: the similar names. | `undefinedNames` |
| `unknown-method` | warning | A method call names no method of the receiver's type (an accumulator, a vertex, an edge, a vertex set, a JSON value or a FILE), but one with a similar name exists (`@@l.sise()` for `size`); on a declared accumulator of a built-in type (`@@x`, `@x`, `v.@x`) every method the type's documentation does not list is reported (`@@x.resize(1)` on a BitwiseOrAccum). Quick fix: the similar names. | `undefinedNames` |
| `unknown-type-name` | warning | A declaration uses a type name that is not a tuple, accumulator type or keyword, but a similar one exists. `PIRNT x;` reads as a declaration of `x` with type `PIRNT`, so misspelled statement keywords show up here too. Quick fix: the similar names. | `undefinedNames` |
| `unknown-type` | warning | A vertex or edge type is not declared in the workspace. Checked in queries, loading jobs, edge endpoints, `CREATE GRAPH` member lists and in what schema change jobs and `ALTER` statements name (`ALTER VERTEX`/`EDGE`, `ADD EDGE` endpoints, `ADD ... TO GRAPH`, `ALTER GRAPH ... ADD`); types added by `ADD VERTEX`/`EDGE` in any job count as declared. `DROP` statements are not checked: they often name types that no longer exist in the schema files. Quick fix: similar names. | `unknownTypes` |
| `graph-without-edges` | information | `CREATE GRAPH g (v, ...)` lists vertex types and no edge type, all members being known. The TigerGraph documentation disagrees with itself: its `exitOnError` example rejects such a graph ("There is no edge type specified!") while another example creates and loads a vertex-only graph, so this is only a hint. Not shown for `(*)`, an empty list, unknown members or tag-based graphs. | `languageRules` |
| `unknown-graph` | warning | The graph named by `CREATE QUERY`, `CREATE LOADING JOB` or `CREATE SCHEMA_CHANGE JOB ... FOR GRAPH` or by `USE GRAPH` is not created by any `CREATE GRAPH` in the workspace. Only checked when the workspace creates at least one graph; membership of types in graphs is not modelled. | `unknownTypes` |
| `unknown-attribute` | warning | The vertex or edge type has no such attribute (vector attributes added with `ALTER VERTEX ... ADD VECTOR ATTRIBUTE` count; the `PRIMARY_ID` of a vertex type is no attribute unless the type is declared `WITH primary_id_as_attribute="true"`; an alias with no type of its own takes it from the schema edge before it when that decides a type: `-(ACTED_IN>)- :m`). Quick fix: similar names. | `unknownAttributes` |
| `duplicate-definition` | warning / hint | A `CREATE VERTEX`, `CREATE ... EDGE`, `CREATE GRAPH` or `CREATE QUERY ... FOR GRAPH g` repeats a name that an earlier `CREATE` defines; the database rejects it. Not reported for `CREATE OR REPLACE`, `ADD VERTEX`/`EDGE` in schema change jobs, queries without `FOR GRAPH`, queries of different graphs, or names that a `DROP` in any file of the workspace removes. A repeat in the same file is a warning with a link to the first definition. The order of files is unspecified, so a repeat in another file is reported as a hint on the file whose URI sorts later. | `duplicateDefinitions` |
| `unused` | hint | An accumulator or variable is never used (shown faded). Quick fix: remove the declaration. | `unused` |
| `argument-count` | warning | A query is called (or run) with the wrong number of arguments, or a built-in function or method (`abs()`, `substr(s)`, `@@list.size(1)`) with a number outside the range its signature allows. Variadic and irregular signatures (`coalesce`, `count(DISTINCT x)`, `LOG`) are not checked. Parameters passed by name, as one JSON object (`RUN QUERY q({"name": "Emma"})`), are checked by name instead. `get`, `containsKey` and `remove` of a GroupByAccum take as many arguments as it has keys. | — |
| `argument-name` | warning | A JSON object of parameters names a parameter the query does not have. Quick fix: similar parameter names. | — |
| `argument-type` | warning | A literal argument cannot be a value of the parameter's type: a string or a fraction for an INT, a negative number for a UINT, a number for a BOOL, a list for a single value. Also a string for a number or BOOL parameter (or a boolean for a number) when the argument is a variable, accumulator or a subquery result of known kind (that part is a language rule). | `languageRules` (variable and subquery arguments only) |
| `reserved-word` | error / warning | The name is a reserved word: the compiler rejects it for query identifiers (`INT count`) and for vertex types, edge types, graphs, tags and attributes (`type`, `Order`). Vertex and edge types named after query reserved words, or after lowercase C++ keywords such as `friend`, get a warning because queries cannot refer to them. Quick fix: rename to `name_`. | `languageRules` |

## Values of LOAD and INSERT statements

| Code | Severity | Meaning | Setting |
| --- | --- | --- | --- |
| `value-count` | warning / error | The VALUES list has more or fewer values than the vertex or edge type has attributes (a warning, as the schema in the workspace may lag behind the database), or than the columns listed in the statement (an error). For edges the first two values are the source and target. `flatten()` and `flatten_json_array()` count as the columns they produce. | — |
| `value-skip` | error | A LOAD statement skips the primary id with `_`. | — |
| `endpoint-type` | warning | The edge type is declared `FROM *, TO *`, so a LOAD statement must give the vertex type after each endpoint id: `VALUES ($0 Person, $1 Company)`. | — |

## Accumulators

| Code | Severity | Meaning | Setting |
| --- | --- | --- | --- |
| `accumulator-assignment` | error | A global accumulator is assigned with `=` inside ACCUM or POST-ACCUM; there it can only accumulate (`+=`). | `languageRules` |
| `accumulator-mutator` | error | A method that modifies an accumulator (`clear`, `remove`, `pop`, `resize`, `update`, ...) is called where GSQL forbids it: in PRINT, on a global accumulator inside a SELECT block, or on a vertex-attached accumulator outside POST-ACCUM. | `languageRules` |
| `accumulator-declaration` | error | A vertex- or edge-attached accumulator is declared inside a FOREACH or WHILE loop. | `languageRules` |
| `loop-control` | error | BREAK or CONTINUE outside a WHILE or FOREACH loop (the language reference allows them only inside the block of one). | `languageRules` |
| `foreach-variables` | error | FOREACH binds the wrong number of variables for what it iterates: a MapAccum or MAP binds a key and a value, `FOREACH (k, v) IN @@map`, and a SetAccum, BagAccum, ListAccum, SET, BAG or LIST of plain values, or a vertex set, one element. | `languageRules` |
| `edge-accumulator` | error | An edge accumulator (`SumAccum<INT> EDGE @w`) is used in POST-ACCUM. | `languageRules` |
| `accumulator-type` | error / warning | An invalid accumulator type: the wrong number of type arguments (MapAccum takes two, `MapAccum<key_type, value_type>`; SumAccum, MaxAccum, MinAccum, ListAccum, SetAccum, BagAccum, ArrayAccum and HeapAccum one; OrAccum, AndAccum and the bitwise accumulators at most one; a GroupByAccum needs at least one key and one accumulator, a TYPEDEF'd accumulator counting as one), GroupByAccum keys after its accumulators or two GroupByAccum fields with the same name (names are case-sensitive: `a` and `A` are two fields), a SumAccum of anything but INT, UINT, FLOAT, DOUBLE or STRING (`SumAccum<BOOL>`; `STRING COMPRESS` is accepted and only `deprecated`), a bit length given to any other accumulator, a named argument outside GroupByAccum, a GroupByAccum key or accumulator without a name, a HeapAccum as a MapAccum value, an accumulator as a MapAccum key, an accumulator inside a SetAccum or BagAccum, a non-ListAccum inside a ListAccum, ListAccum nested more than three levels, or an accumulator as the parameter type of a query without RETURNS (reported once, without the checks of its arguments). Warnings, because the documentation only shows the usual form and does not say a compiler rejects the other: a type argument of AvgAccum, DeviationAccum or DeviationPAccum (`AvgAccum<DOUBLE>`; their data type is not declared; quick fix: remove `<...>`), and a bitwise accumulator whose argument is not a bit length, a number or a parameter (`BitwiseOrAccum<INT>`), and an accumulator as the parameter type of a subquery, a query with RETURNS, which the documentation neither shows nor rules out. | `languageRules` |
| `accumulator-input` | error | A value of the wrong shape given to an accumulator with `+=` or `=` (also in ACCUM and POST-ACCUM, on vertex-attached accumulators, on TYPEDEF'd accumulators, and as the initial value of a declaration). A MapAccum takes `(key -> value)` pairs and a GroupByAccum `(k1, k2 -> v1, v2)` pairs with as many keys and accumulator values as it declares: reported are a tuple without `->` (`("a", 1)`; quick fix: replace the comma with `->`), a literal or a value of known scalar kind (arithmetic, bitwise operators, comparisons, `IN`, `LIKE`, `IS NULL`, `BETWEEN`; one error, without an arithmetic or comparison warning on the same expression), a set, list, bag, vertex, edge or accumulator other than a map (`@@map += @@set`), a pair with the wrong number of keys or values (`(k -> 1, 2)` for a MapAccum), a nested MapAccum value that is not itself a pair, a tuple or list given to a single-value accumulator such as a `SumAccum<INT>` map value, and a pair given to any other accumulator (`SetAccum<INT> += ("a" -> 1)`). A parenthesized `(k - v)`, `(k > v)` or `(k >> v)` is reported as a mistyped `->` instead of as arithmetic or a comparison; quick fix: replace the operator with `->`. Values of unknown type (calls, variables without a declared type) are not judged, nor are subscripted targets (`@@m[k] += ...`) or tuples given to ListAccum, SetAccum or BagAccum (they may be collection literals). | `languageRules` |
| `accumulator-read-after-write` | warning (hint when the update is a plain `=`) | An accumulator (`@@n`, `v.@n`) is read in a later statement of the same ACCUM clause that updates it. All executions of ACCUM read the same snapshot, so the read sees the value from before the clause, not the running total; read it in POST-ACCUM. See [accumulator-semantics.md](accumulator-semantics.md). | `languageRules` |
| `accumulator-case` | warning | Accumulator type names are case-sensitive (`sumaccum` should be `SumAccum`). Quick fix: correct the case. | `languageRules` |

## Queries

| Code | Severity | Meaning | Setting |
| --- | --- | --- | --- |
| `v3-comparison` | warning | `=` and `<>` compare values only in `SYNTAX V3` queries (TigerGraph 4.1.3 and later); V2, the default, uses `==` and `!=`. Quick fixes: use `==`/`!=`, or declare the query `SYNTAX V3`. | — |
| `cypher-syntax` | warning | An openCypher pattern (`FROM (p:Person)-[e:Knows]-(q)`) in a query that declares `SYNTAX V1` or `SYNTAX V2`; the reference says those are rejected. Queries without a declaration are not judged, because the 4.2 reference writes such patterns in default-syntax queries. Reported once per query. Quick fix: declare the query `SYNTAX V3`. | `languageRules` |
| `limit-offset` | error | `LIMIT k OFFSET j` without ORDER BY: offsets need a known order, and the query compiler rejects it. | `languageRules` |
| `kleene-edge-alias` | error | An edge alias on an edge pattern repeated with `*` or `*m..n` (`-(E>*1..3:e)-`); the number of edges varies, so the alias binds no single edge. | `languageRules` |
| `having-alias` | error | A SELECT block that selects one vertex alias has a HAVING clause using another vertex alias of its FROM patterns (`SELECT v ... HAVING tgt.subject == "cats"`); the query compiler rejects it (SEM-50). | `languageRules` |
| `per-alias` | error | A SELECT block with a PER clause selects a vertex alias, or uses one as `alias.attr` or `alias.@acc` in ACCUM or POST-ACCUM, that is not listed in the PER clause. | `languageRules` |
| `pattern-join` | warning | The comma-separated patterns of a FROM clause cannot be naturally joined: a pattern shares no vertex alias with the others. Judged only when every pattern has an edge and every vertex has an alias. | `languageRules` |
| `type-mismatch` | warning | A value of a kind that cannot be right: a value of another kind than an accumulator takes (a string or BOOL added to a numeric accumulator, `SumAccum<INT> += name`, also Max/Min/Avg/Set/Bag/List of numbers; a number added to a `ListAccum<STRING>` or `SumAccum<STRING>`; a string or number added to an OrAccum or AndAccum; a vertex, edge, collection or accumulator that holds several values (SetAccum, BagAccum, ListAccum, MapAccum, ArrayAccum, HeapAccum, GroupByAccum) added to a single-value accumulator; AvgAccum, DeviationAccum and DeviationPAccum read as a DOUBLE and the bitwise accumulators as an INT, so `@@sum += @@bits` is fine; the message says "stored in" for `=` and initial values, "added to" for `+=`; the same for the accumulator values of MapAccum and GroupByAccum pairs such as `("a" -> "x")` for a `MapAccum<STRING, SumAccum<INT>>`), a key or plain value of a MapAccum or GroupByAccum pair of another kind than declared (`(1 -> 1)` or `(s -> 1)` with a vertex `s` for `MapAccum<STRING, ...>`, a literal for a tuple type), a map merged into a MapAccum whose keys have another kind (`@@stringKeyed += @@intKeyed`), a key of another kind given to `get`, `containsKey` or `remove` of a MapAccum or GroupByAccum, a string stored in a numeric or BOOL variable (`INT x = "abc"` or `x = "abc"`), a string returned by a query that RETURNS a number or BOOL, a `RETURN` with a value in a query that has no RETURNS clause, a number compared with a string (`a.n == "7"`; also `<>`, `=` in `SYNTAX V3` queries, and `{age: "abc"}` property maps of patterns), or arithmetic (`-`, `*`, `/`, `%`, unary `-`) with a string. Also the result of a subquery that RETURNS a number, string or BOOL is judged like such a value, and a query without RETURNS used as the value of a declaration or assignment is reported. Only values of certain kind are judged: literals, variables, attributes, accumulators with a declared type and subquery results. | `languageRules` |
| `float-equality` | warning | Exact equality between FLOAT or DOUBLE values; the query compiler warns about it too. Comparisons with whole numbers (`x == 0`, `x == -1`, `x == 2.0`) and the whole-number test `x == float_to_int(x)` (also `floor`, `ceil`, `round`, `trunc` of the same expression) are exact and not reported. Quick fix: `abs(a - b) < 0.0001`. | `floatEquality` (and `languageRules`) |
| `virtual-edge` | error | A virtual edge type is declared inside a nested statement (it must be at the top level of the query body), has a DISCRIMINATOR, or is combined with other edge types in one edge pattern. | `languageRules` |
| `interpreted-mode` | warning | `INTERPRET QUERY` does not support the feature: FILE objects and parameters, BAG parameters, PRINT ... TO_CSV, RAISE, TRY, RETURN, ArrayAccum, the `'` operator, IS NULL, JSONOBJECT/JSONARRAY, `_` or ANY as the source of a pattern, vertex types in INSERT values, some functions (`coalesce`, `evaluate`, `datetime_format`, `parse_json_*`, `SelectVertex`, `LoadAccum`, `neighbors`, `neighborAttribute`), and a parameter sharing a name with a global accumulator. Install the query instead. | `languageRules` |
| `distributed-mode` | warning | A `DISTRIBUTED` query uses `evaluate()`, `neighbors()`, `neighborAttribute()` or `edgeAttribute()`, or calls another distributed query; or a query calls a distributed query inside ACCUM or POST-ACCUM. | `languageRules` |
| `deprecated` | hint | A deprecated feature: `STRING COMPRESS`, tag-based access control (`ADD TAG`, `TAGS (...) BY`) and tag-based graphs (`PRINT ... WITH TAGS`). | `languageRules` |

## Style

Hints for deviations from TigerGraph's
[GSQL Style Guide](https://www.tigergraph.com/docs/gsql-ref/4.3/appendix/gsql-style-guide)
(an appendix of the language reference). They only nudge: both have a quick fix that is
safe without review, so "fix all" applies them. The style guide's indentation rule
(4 spaces, no tabs) is the formatter's job: `gsql-lsp format` and the editor's format
command indent by 4 spaces unless the editor says otherwise.

| Code | Severity | Meaning | Setting |
| --- | --- | --- | --- |
| `keyword-case` | hint | A keyword or reserved word is not in all caps (`select`, `Select`; also `true`, `false` and `null`, which are reserved words): "Always write keywords and reserved words in all caps". Quick fix: change to upper case. Names, strings, comments and accumulator type names are never touched. | `style` |
| `hash-comment` | hint | A comment starts with `#`: "Use `//` for single line and inline comments", "Do not use `#`" (the coming GQL standard has no `#` comments). Quick fix: change `#` to `//`. | `style` |
